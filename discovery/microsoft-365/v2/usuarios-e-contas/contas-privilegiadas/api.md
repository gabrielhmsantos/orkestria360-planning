# APIs — Contas Privilegiadas

| Endpoint | Estrutura de resposta `200` |
| --- | --- |
| `GET /directoryRoles` | `{ "value": DirectoryRole[] }`; item: `id`, `displayName`, `description`, `roleTemplateId`. Não aceita `$top` neste tenant. |
| `GET /directoryRoles/{role-id}/members` | `{ "value": DirectoryObject[] }`; item mínimo: `@odata.type`, `id`; com dados tipados/selecionados pode conter atributos de `user`, `group` ou service principal. Coleção vazia significa role sem membros. |
| `GET /roleManagement/directory/roleAssignments` | `{ "value": UnifiedRoleAssignment[], "@odata.nextLink": string? }`; item: `id`, `roleDefinitionId`, `principalId`, `directoryScopeId`, `appScopeId`, `createdDateTime`. |
| `GET /roleManagement/directory/roleDefinitions` | `{ "value": UnifiedRoleDefinition[] }`; item: `id`, `displayName`, `description`, `isBuiltIn`, `isEnabled`, `resourceScopes`, `rolePermissions[]`. A coleta validou `200` sem `$top`; neste tenant `$top` retorna `400`. |
| `GET /roleManagement/directory/roleEligibilityScheduleInstances` | `{ "value": UnifiedRoleEligibilityScheduleInstance[], "@odata.nextLink": string? }`; item: `id`, `principalId`, `roleDefinitionId`, `directoryScopeId`, `appScopeId`, `startDateTime`, `endDateTime`, `memberType`, `roleEligibilityScheduleId`. Aceita `$select`, `$filter` e `$expand`; permissão app mínima: `RoleEligibilitySchedule.Read.Directory`. |
| `GET /roleManagement/directory/roleAssignmentScheduleInstances` | `{ "value": UnifiedRoleAssignmentScheduleInstance[], "@odata.nextLink": string? }`; item: `id`, `principalId`, `roleDefinitionId`, `directoryScopeId`, `appScopeId`, `startDateTime`, `endDateTime`, `memberType`, `roleAssignmentScheduleId`, `assignmentType` e `roleAssignmentOriginId`. Aceita `$select`, `$filter` e `$expand`; permissão app mínima: `RoleAssignmentSchedule.Read.Directory`. |
| `GET /reports/authenticationMethods/userRegistrationDetails` | Envelope `value[]`; item com `isAdmin`, `isMfaRegistered`, `isMfaCapable`, `methodsRegistered[]`, `defaultMfaMethod`, `lastUpdatedDateTime` e identidade. |
| `GET /identityProtection/riskyUsers` | Envelope `value[]`; item com `id`, `userPrincipalName`, `riskLevel`, `riskState`, `riskDetail` e `riskLastUpdatedDateTime`. |

Todas as chamadas são `GET` sem corpo. Correlacionar `principalId` com `/users` e `roleDefinitionId` com `roleDefinitions` para nome, status e atividade. A validação app-only atual das duas rotas PIM devolveu `400` com `error.code: AadPremiumLicenseRequired` e mensagem de que o tenant requer Entra ID P2 ou Governance. Portanto este é o estado `restricted` observado neste tenant; não é coleção vazia. Se, em tenant licenciado, a resposta for `200 { "value": [] }`, ela deve ser registrada como `empty_valid_response`. Roles permanentes continuam cobertas por `/directoryRoles` e `roleAssignments`. `riskyUsers` requer Entra P2 e consentimento próprio; `403` não deve ser convertido em coleção vazia. Break Glass, proprietário e conta compartilhada exigem catálogo interno e ficam `unavailable` sem ele.
